# Implementation

Use an independent declarative action catalog for the sixteen existing command handlers and the public shortcut paths. Store sparse `commands.<action>` lists, expanded `keybindings` leaves (existing `keybindings.dashboard` paths preserved), and `pauseOrder` (`together`, `goal-first`, `turn-first`) in the existing locked global/project settings layers. Resolve and report provenance per action/leaf. Validate syntax centrally; compare conflicts by overlapping input contexts and normalized key identities. Disabled arrays must remain distinct from inheritance. Mutations retain existing atomic writes and concurrent merge guarantees.

Build command roots from the effective configuration on extension load and dispatch longest complete-word routes to the existing handlers. Preserve the fixed `/goal-settings` recovery route. Use Pi's public registration and argument completion API. Pi has no public command unregister API: apply route changes through an explicit idle reload from the controls screen and display pending status until then. Keep key handling live through the existing terminal input listener and cached settings. No model tools or profiles are added. Existing instructions use configured command spellings; default prompt fixtures stay unchanged and the controls registry never enters model context.

Pi's boundary `continue` flag requests an extra model turn; returning false does not stop the normal tool loop. Goal-first therefore uses the public abort at the finished-turn boundary. Pi displays its normal abort status after the completed tool output; no host internals or transcript messages are patched.

Encapsulate interruption state in the goal core. A turn-only hold belongs to one goal and session, suppresses the abort-to-pause cascade for that interrupted run, clears pending continuation/recovery and prevents scheduling/claiming while held. Ordinary user work or explicit resume clears it. Focus replacement and session teardown clear old interruption state. Existing SDK signal and `agent_settled.aborted` compatibility paths consult the same decision. Goal-first uses the durable paused goal status and stops the host at `turn_end` after the in-flight turn finishes, preventing another provider request; a second key press aborts immediately. A resume before abort settlement must arm its saved continuation once the host settles. A refused resume leaves the hold intact.

Implement a custom bounded Controls component using Pi's theme, Input, key parser and UI custom component API. Separate pure catalog, parsing, conflict/route logic, screen model and render/input logic so behaviour can be tested without a model. Commands, key lists and pause order share scope and inheritance affordances. Capture keys before the global goal handler by using the existing modal-depth guard. Custom goal questionnaires and confirmation dialogs use the same declarative `keybindings.dialog` controls; their context is separate from live goal shortcuts. Settings navigation retains Pi's own controls for recovery. Keep modal cleanup exception-safe.

Validation: focused parser/layering/routing and interruption tests; rendered widths/heights and input state transitions; full type/lint/test checks; actual installed Pi 1.4 CLI walkthrough with isolated settings/provider and captured screens; supported old SDK boundary checks for changed public APIs; focused context/performance checks where relevant. Record iterations, failures and results in MILESTONES.md.
